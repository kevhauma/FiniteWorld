# Fabric worldgen in code (26.x)

The other skills cover JSON worldgen and general Fabric setup. This one covers the
seam where vanilla generation is extended from Java: new registry *types* that
JSON then references.

## First: ground truth is the vanilla source

APIs in generation code shift between drops and are not covered by Fabric API.
Before writing or changing any class that touches generation, read the vanilla
class you are extending or calling, at the project's exact Minecraft version:

- 26.x is unobfuscated and Fabric uses Mojang's official names, so the sources
  Loom attaches in the IDE (or `./gradlew genSources`) are the real names.
  Browse without a checkout at <https://mcsrc.dev>.
- Starting classes (`net.minecraft.world.level.levelgen` and neighbours):
  `DensityFunction`, `DensityFunctions`, `NoiseRouter`, `NoiseRouterData`,
  `NoiseGeneratorSettings`, `RandomState`, `NoiseChunk`, `Climate`,
  `MultiNoiseBiomeSource`, `presets.WorldPreset(s)`,
  client `gui.screens.worldselection.PresetEditor` and `CreateWorldScreen`.
- The data files are generated by vanilla: run the server jar with
  `--reports` (or read `data/minecraft/worldgen/**` from the client jar) to get
  the exact `noise_settings/overworld.json` and density function graph to copy.

Treat any signature in this skill as a pointer to look up, not as authoritative.

## Shape of a code-driven worldgen mod

Keep vanilla doing the work; add the smallest new type and wire it in with data.

1. **Custom density function type.** Implement `DensityFunction` (or
   `DensityFunction.SimpleFunction` when it has no child functions). Give it a
   `MapCodec`, wrap it in `KeyDispatchDataCodec.of(...)` returned from
   `codec()`, and register the `MapCodec` in
   `BuiltInRegistries.DENSITY_FUNCTION_TYPE` under `<modid>:<name>` in the
   mod initializer. JSON then uses `{"type": "<modid>:<name>", ...}`.
2. **Noise settings and density graph.** Terrain does not read the
   `noise_router` climate entries. Vanilla's terrain functions (`offset`,
   `factor`, `jaggedness`, and through them `depth`, `sloped_cheese`,
   `final_density`) read `minecraft:overworld/continents`, `erosion` and
   `ridges` **by id**, so swapping router entries alone changes biomes and
   leaves terrain alone. Copy the climate-dependent functions from
   `data/minecraft/worldgen/density_function/overworld/` under
   `<modid>:overworld/`, wrap the inputs with your type, and rename the
   references in the copies and in a copy of `noise_settings/overworld.json`
   (router, `aquifers`, `debug_functions`). Overriding the vanilla ids instead
   changes every normal world too. Take the router's fields from the vanilla
   file; in 26.3 they are `chunk_surface_level`, `continents`, `depth`,
   `erosion`, `final_density`, `ridges`, `temperature` and `vegetation`.
   Finite World's copy list is in `docs/design.md` (*Copied density function
   graph*).
3. **World preset.** `data/<modid>/worldgen/world_preset/<name>.json` pointing
   the overworld dimension at the new noise settings. Add the preset id to
   `data/minecraft/tags/worldgen/world_preset/normal.json` (`"replace": false`)
   to list it on the Create World screen.
4. **Customise screen.** Vanilla maps preset keys to `PresetEditor`s (that is how
   Superflat and Single Biome get their Customize button). Registering one for
   your preset needs a client-side mixin/accessor on that map; the editor
   rebuilds the `WorldDimensions` with the user's values. Client code lives in
   the client source set only.
5. **Per-world parameters** (a radius, a band width) belong in the density
   function's codec fields, so they are saved with the world's generator
   settings and survive reloads without extra persistence.

## Rules for generation code

- **Deterministic and pure.** Output is a function of (seed, settings, position)
  only. Chunks generate in parallel on worker threads: no mutable statics, no
  `Random` without a seed, no world access from a density function.
- **Seeded noise.** Hold noise as `DensityFunction.NoiseHolder` and implement
  `mapAll(visitor)` so `RandomState` wires seeded noise in (`visitor.visitNoise`).
  If you need the raw seed or a precomputed plan, find where `RandomState`
  builds the router and hook there; compute once per `RandomState`, never per
  sample.
- **Hot path.** `compute` runs per noise cell, millions of times per chunk batch:
  no allocation, no boxing, no map lookups. Return honest `minValue()` /
  `maxValue()`; vanilla uses them to skip work. Wrap expensive 2D inputs in the
  vanilla cache markers (`flat_cache`, `cache_2d`) in JSON instead of caching by hand.
- **Data over code over mixins.** JSON first; a new registered type second;
  a mixin only where no data or registry hook exists. In mixins prefer
  MixinExtras (`@WrapOperation`, `@ModifyExpressionValue`, `@ModifyReturnValue`)
  and `@Accessor`/`@Invoker` over `@Redirect`, `@Overwrite` or reflection.
  For visibility only, use a class tweaker (formerly access widener; still
  named `accessWidener` in `build.gradle` / `fabric.mod.json`), check it with
  `./gradlew validateAccessWidener`.
- **Testable core.** Put the math (falloff curves, planners, scoring) in plain
  Java classes with no Minecraft types, and unit test them with JUnit
  (see `java-junit`). Use Fabric game tests only for what needs a world
  (see `minecraft-testing`).

## Verifying in game

- `./gradlew runClient`, create a world with the preset, then `/locate biome`
  and `/locate structure` for checklist items, F3 for climate values at a spot.
- Visualise density functions and noise settings at <https://misode.github.io>
  before wiring them in.
- Profile generation with the spark mod (`/spark profiler`) after big changes.

## Java toolchain

- 26.x needs **JDK 25**. Check with `java -version` and `./gradlew --version`;
  the Gradle daemon JVM must be 25 too. Pin it with a Gradle toolchain
  (`java { toolchain { languageVersion = JavaLanguageVersion.of(25) } }`).
- Always run Gradle through the wrapper (`./gradlew`, `gradlew.bat`), never a
  global `gradle`. Audit the build with `gradle-best-practices`.
- Look up current Minecraft, Loader, Fabric API and Loom versions at
  <https://fabricmc.net/develop> instead of trusting remembered numbers; the
  template generator there is the right start for a new project.
